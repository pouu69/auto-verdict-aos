## 4. 게시 방법 (업데이트 릴리스 절차)

### 4.1 핵심 개념 — "게시 개요"에 제출해야 반영된다
- Play Console에서 스토어 정보·정책 선언·프로덕션 버전을 저장해도 **바로 반영되지 않는다.** 모두 "임시 변경사항"으로 쌓이고, **게시 개요 → "검토를 위해 변경사항 N개 제출"**을 눌러야 Google 심사로 간다.
- **관리형 게시가 꺼져 있어** 승인되는 즉시 공개된다.
- **내부 테스트는 예외** — 심사 없이 테스터에게 바로 배포된다. 그래서 내부 테스트로 설치되는 앱에는 아직 심사 전인 콘텐츠 등급이 반영되지 않아 "17세 이상"처럼 보일 수 있다(심사 승인 후 3세 이상으로 바뀜).
- **처음 출시할 때는 스토어 정보·정책 선언·프로덕션 버전을 모두 준비해 한 번에 제출하는 것이 일반적**이다. 따로 나눠 제출하면 심사를 두 번 기다리게 된다.
- **심사 기간:** 첫 심사는 보통 며칠~7일 안팎, 이후 업데이트는 보통 몇 시간~1~2일. 결과는 Play Console 알림과 pouu69@gmail.com 메일로 온다.

### 4.2 버전 규칙
- **versionCode는 업로드할 때마다 +1.** 한 번 Play에 올린 versionCode는 출시하지 않았어도 **다시 쓸 수 없다.**
- versionName은 사용자에게 보이는 버전. 버그만 고친 재업로드는 그대로 둬도 된다(예: versionCode 5 → 6, versionName 1.1.0 유지).
- 변경: `app/build.gradle.kts`의 `versionCode` / `versionName`, 그리고 `RELEASE_NOTES.md`.

| versionCode | versionName | 상태 |
|---|---|---|
| 3 | 1.0.2 | 업로드만 함 (개편 전, 미출시) |
| 4 | 1.0.2 | 내부 테스트 초안만 (미출시) |
| 5 | 1.1.0 | 내부 테스트 출시 (UX 개편) |
| 6 | 1.1.0 | 내부 테스트 출시 + **프로덕션 심사 중** (하단 시트 스크롤 수정) |

### 4.3 빌드
```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
(cd webview-bundle && npx vitest run)                 # webview 테스트
./gradlew :app:testDebugUnitTest :app:bundleRelease  # Kotlin 테스트 + 서명된 AAB
"$JAVA_HOME/bin/jarsigner" -verify app/build/outputs/bundle/release/app-release.aab   # "jar verified."
```
- 결과물: `app/build/outputs/bundle/release/app-release.aab` (약 10MB, Play 신규 설치 크기 약 6.2MB)
- `keystore.properties`가 없으면 서명되지 않은 AAB가 나온다 → 업로드 거절.
- webview 빌드는 Gradle이 nvm의 최신 Node를 자동으로 고른다. npm은 `webview-bundle/.npmrc`로 **공식 레지스트리**(registry.npmjs.org)에 고정되어 있다(사내 레지스트리는 외부 네트워크에서 접속 불가).

### 4.4 Play Console 업로드 순서
1. **내부 테스트** → "새 버전 만들기" → AAB 업로드 → 출시명 `N (x.y.z)`, 출시 노트(`<ko-KR>…</ko-KR>`, `RELEASE_NOTES.md`에서 복사) → 임시보관함에 저장 → 다음 → 미리보기 확인 → **저장 및 출시**
2. 테스트 폰(Play 스토어 계정 = 테스터 목록의 이메일)에서 업데이트 설치 후 QA. **모바일 데이터로 테스트**(개발 PC와 같은 Wi-Fi면 공인 IP가 같아 엔카 차단 영향을 받을 수 있음).
3. **프로덕션** → "새 버전 만들기" → "라이브러리에서 추가"로 같은 버전 선택(또는 내부 테스트의 "버전 승급") → 출시 노트 → 저장 → 미리보기 → 저장
4. **게시 개요 → "검토를 위해 변경사항 N개 제출"** → 사전 점검(수 분) 후 심사로 전송
5. 승인 → 즉시 대한민국에 공개

### 4.5 미리보기 경고 중 무시해도 되는 것
- "네이티브 코드를 포함하며 디버그 기호가 업로드되지 않았습니다" — AAB 안의 네이티브 라이브러리는 Compose가 쓰는 `libandroidx.graphics.path.so`뿐이고, 기호가 제거된 채 배포되어 올릴 기호 파일이 없다. 출시·심사에 영향 없음.

## 5. 스토어 자산 바꾸기

### 5.1 문구
[store-listing.md](./store-listing.md)를 고친 뒤 Play Console → 사용자 늘리기 → 스토어 등록정보 → 기본 스토어 등록정보에 입력 → 다음 → 저장 → 게시 개요에서 제출.

### 5.2 스크린샷
- 만드는 방법(틀·캡션·합성): [assets-guide.md](./assets-guide.md) 3절. 휴대전화 스크린샷은 **9:16 비율**이어야 한다(에뮬레이터 원본 1080×2400은 그대로 못 올림 → 틀에 넣어 1080×1920).
- **엔카에 요청을 보내지 않고 찍는다:** 에뮬레이터(`AV_API_36`)에서 먼저 매물을 분석해 두고(최근 본 차 캐시 24시간 유지), **비행기 모드를 켠 뒤** 최근 본 차에서 결과 화면을 열어 찍는다. 광고 자리도 비어 있게 찍힌다.
- 판정이 다양하게 보이도록 매물을 고른다(현재: BMW 320d '주의' 89점, 라세티 '피하세요' 72점, 벤츠 E-클래스 '괜찮아요' 100점).
- 프레임에 보이는 것은 캡처 위쪽 약 1520px(1080 폭 기준 약 1820px)뿐이다. 보여 줄 내용을 화면 위쪽에 둔다.

### 5.3 Play Console에 그래픽 올릴 때 주의
- 애셋 라이브러리에 **같은 파일 이름**이 이미 있으면 헷갈리므로 이름을 바꿔 올린다(예: `r3-01.png`, `play-icon-512-v2.png`).
- 스크린샷을 지울 때 슬롯이 비면 삭제 범위가 위쪽(아이콘·피처 그래픽)까지 넓어지는 일이 있었다. **지운 뒤 아이콘·피처 그래픽이 남아 있는지 확인**하고 저장한다. "일부 언어에 오류가 있습니다"가 뜨면 빈 슬롯("애셋을 1개 이상 업로드하세요")이 있는지 본다.

1. `docs/privacy-policy.md`(원문)와 `docs/legal/index.html`(공개용)을 같이 고친다. **데이터 보안 답변(3.3)과 내용이 맞아야 한다** — 심사는 공개 URL의 방침과 신고 내용을 대조한다.
2. 공개 페이지는 `main`의 `docs/legal`이 아니라 **`gh-pages` 브랜치의 `index.html`** 이 배포된다. main을 push해도 공개 페이지는 바뀌지 않는다.
   ```bash
   git worktree add ../av-ghp gh-pages
   cp docs/legal/index.html ../av-ghp/index.html
   (cd ../av-ghp && git commit -am "chore: update privacy policy to YYYY-MM-DD" && git push origin gh-pages)
   git worktree remove ../av-ghp
   ```

4. 데이터 처리 방식이 바뀌었다면 Play Console 데이터 보안 양식도 고치고 게시 개요에서 제출한다.

## 7. 업로드 키 (서명)
- 업로드 키: `secrets/autoverdict-upload.jks` + 비밀번호가 든 `keystore.properties` (둘 다 `.gitignore` 대상, 이 Mac에만 있음). **비밀번호 매니저·클라우드 등 2곳 이상에 백업한다.**
- Play 앱 서명 사용 중 — Google이 앱 서명 키를 관리하고, 위 키는 "업로드 키"로만 쓴다. 공개 트랙에 게시하면 앱 서명 키 선택은 고정된다.
- 업로드 키를 잃어버리면 Play Console → 앱 무결성 → 앱 서명에서 **업로드 키 재설정**을 요청해야 한다(앱을 새로 만들 필요는 없음).
- 생성·검증 명령: [release-guide.md](./release-guide.md)

## 8. 공개된 뒤 할 일
1. **AdMob 스토어 연결:** AdMob → 앱 → AutoVerdict → "스토어 추가" → Google Play에서 `com.kcurve.autoverdict` 검색 → 연결. 연결 전에는 "광고 게재가 제한됨" 상태라 광고가 거의 나오지 않는다. **앱이 Play에 공개된 뒤에만 검색된다**(내부 테스트 상태에서는 검색 안 됨).
2. **모니터링:** Play Console → 모니터링 및 개선(비정상 종료·ANR), AdMob 노출·수익.
3. **선택:** 스토어 설정에 개발자 웹사이트를 넣고 그 사이트에 `app-ads.txt`를 올리면 광고 수익에 유리하다.

## 9. 겪은 문제와 교훈
- **패키지 이름 충돌:** `com.car.autoverdict`는 Play에서 다른 계정이 이미 쓰고 있었다. applicationId만 `com.kcurve.autoverdict`로 바꾸고 코드 namespace는 그대로 뒀다.
- **업로드 키 분실:** 예전 PC에서 만든 키스토어가 없어 새로 만들었다(첫 등록 전이라 문제없었음). → 7절 백업.
- **targetSdk:** 2026-08-31부터 신규 앱·업데이트는 targetSdk 36 이상이어야 한다(Robolectric도 SDK 36 지원 버전 필요).
- **엔카 봇 차단:** 스크린샷용 매물을 찾으려고 엔카 API에 대량 병렬 요청(약 1,000건)을 보냈다가 개발 PC의 IP가 차단됐다. **엔카 등 외부 서비스에는 실제 사용자 수준(몇 건, 간격 두고)만 요청한다.** 필요한 매물은 사람이 직접 고르거나 캐시·테스트 데이터를 쓴다.
- **"17세 이상" 표시:** 콘텐츠 등급(3세 이상)을 저장만 하고 게시 개요에서 제출하지 않아 생겼다. 내부 테스트 출시는 심사를 거치지 않으므로 등급이 반영되지 않는다.
- **공개 방침 미갱신:** 방침 원문을 고쳤지만 `gh-pages`를 갱신하지 않아 공개 URL이 옛 판이었다. → 6절.
- **스토어 문구와 데이터 보안 불일치:** "외부로 개인정보를 전송하지 않습니다" 같은 문구는 AdMob 데이터 신고와 충돌한다. 문구·방침·데이터 보안 세 곳을 함께 맞춘다.
